## How Spring Boot Starts Internally

When you run `NotesApiApplication.java`:

```
main() is called
  └── SpringApplication.run()
        ├── Creates IoC container (ApplicationContext)
        ├── Scans com.viswa.notesapi for @Component, @Service, @Repository, @Controller
        ├── Creates Bean instances and injects dependencies
        ├── Auto-configures DataSource (PostgreSQL), JPA, Hibernate
        ├── Starts embedded Tomcat on port 8080
        └── App is ready to accept HTTP requests
```

- `show-sql=true` — Prints every SQL Hibernate runs to the console. Gold for debugging.

## Layer 1 — Entity (`Note.java`)

The entity is a Java class that maps directly to a database table.

```java
@Entity
@Table(name = "notes")
@Data
@NoArgsConstructor
@AllArgsConstructor
public class Note {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(nullable = false)
    private String title;

    @Column(columnDefinition = "TEXT")
    private String content;

    @Column(name = "created_at")
    private LocalDateTime createdAt;

    @Column(name = "updated_at")
    private LocalDateTime updatedAt;
}
```

### Annotations Explained

| Annotation | What it does |
|---|---|
| `@Entity` | Tells Hibernate: this class is a database table |
| `@Table(name = "notes")` | Sets the table name explicitly |
| `@Id` | Marks the primary key field |
| `@GeneratedValue(IDENTITY)` | PostgreSQL auto-increments the id |
| `@Column(nullable = false)` | Maps to NOT NULL constraint in DB |
| `@Column(columnDefinition = "TEXT")` | Overrides default VARCHAR(255) to TEXT |
| `@Column(name = "created_at")` | Maps camelCase Java field to snake_case DB column |
| `@Data` (Lombok) | Generates getters, setters, toString, equals, hashCode |
| `@NoArgsConstructor` (Lombok) | Generates empty constructor — JPA requires this |
| `@AllArgsConstructor` (Lombok) | Generates constructor with all fields |

### What Hibernate Does Behind the Scenes

```
Spring starts
  └── Hibernate scans for @Entity classes
        └── Reads Note.java fields + annotations
              └── Generates and runs:

CREATE TABLE notes (
    id         BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    title      VARCHAR(255) NOT NULL,
    content    TEXT,
    created_at TIMESTAMP,
    updated_at TIMESTAMP
);
```

You write Java. Hibernate writes SQL.

## Layer 2 — Repository (`NoteRepository.java`)

The repository is the database access layer. Spring Data JPA generates the implementation at runtime — you only write the interface.

```java
@Repository
public interface NoteRepository extends JpaRepository<Note, Long> {

    List<Note> findByTitleContainingIgnoreCase(String keyword);
}
```

### How Spring Data JPA Works Internally

```
Spring scans for interfaces extending JpaRepository
  └── Creates a Proxy class at runtime (Java reflection)
        └── Proxy implements all methods using Hibernate
              └── Hibernate translates each call to SQL
```

### Free Methods from JpaRepository

| Method | SQL Generated |
|---|---|
| `save(note)` | INSERT or UPDATE |
| `findAll()` | SELECT * FROM notes |
| `findById(id)` | SELECT * WHERE id = ? |
| `deleteById(id)` | DELETE WHERE id = ? |
| `count()` | SELECT COUNT(*) |

### Query Derivation — `findByTitleContainingIgnoreCase`

Spring reads the method name left to right:

```
findBy              → SELECT * FROM notes WHERE
Title               → title
Containing          → LIKE '%keyword%'
IgnoreCase          → LOWER(title) LIKE LOWER('%keyword%')
```

Generated SQL:
```sql
SELECT * FROM notes WHERE LOWER(title) LIKE LOWER('%spring%')
```

Zero SQL written. Spring generated it from the method name.

## Layer 3 — DTO Pattern

DTOs (Data Transfer Objects) control exactly what data crosses the API boundary.

### Why Not Expose the Entity Directly?

- Client could send `id` or `createdAt` and override them
- Sensitive fields added later would leak automatically
- No control over input vs output shape

### NoteRequestDTO — What Client Sends

```java
@Data
public class NoteRequestDTO {
    private String title;
    private String content;
}
```

Client cannot send `id`, `createdAt`, `updatedAt` — those are server-controlled.

### NoteResponseDTO — What Client Receives

```java
@Data
@AllArgsConstructor
public class NoteResponseDTO {
    private Long id;
    private String title;
    private String content;
    private LocalDateTime createdAt;
    private LocalDateTime updatedAt;
}
```

You explicitly choose every field the client sees.

### Data Flow with DTOs

```
Client sends NoteRequestDTO
  └── Service maps to Note entity
        └── Saved to DB
              └── DB returns Note entity
                    └── Service maps to NoteResponseDTO
                          └── Client receives NoteResponseDTO
```

The entity NEVER leaves the service layer.

## Layer 4 — Service (`NoteService.java`)

The service holds business logic. It sits between the controller and repository.

```java
@Service
@Transactional
public class NoteService {

    private final NoteRepository noteRepository;

    public NoteService(NoteRepository noteRepository) {
        this.noteRepository = noteRepository;
    }

    public NoteResponseDTO createNote(NoteRequestDTO requestDTO) { ... }
    public List<NoteResponseDTO> getAllNotes() { ... }
    public NoteResponseDTO getNoteById(Long id) { ... }
    public NoteResponseDTO updateNote(Long id, NoteRequestDTO requestDTO) { ... }
    public void deleteNote(Long id) { ... }
    public List<NoteResponseDTO> searchNotes(String keyword) { ... }

    private Note findNoteById(Long id) {
        return noteRepository.findById(id)
                .orElseThrow(() -> new NoteNotFoundException(id));
    }

    private NoteResponseDTO toResponseDTO(Note note) {
        return new NoteResponseDTO(
                note.getId(), note.getTitle(), note.getContent(),
                note.getCreatedAt(), note.getUpdatedAt()
        );
    }
}
```

### Key Concepts

**Why not call repository from controller directly?**
- One request may need multiple repositories, emails, logging — all in service
- Business logic is testable without HTTP or database
- Changing DB layer only touches repository, not controller

**`@Transactional`**
Wraps every method in a database transaction:
```
method starts → transaction begins
  all DB writes succeed → COMMIT (saved)
  any DB write fails   → ROLLBACK (all cancelled)
```

**Constructor Injection (not `@Autowired` on field)**
```java
// BAD — field injection
@Autowired
private NoteRepository noteRepository;

// GOOD — constructor injection
public NoteService(NoteRepository noteRepository) {
    this.noteRepository = noteRepository;
}
```
Why: field can be `final`, dependency is explicit, easier to unit test.

**`Optional` and `orElseThrow`**
`findById()` returns `Optional<Note>` because the record might not exist.
`.orElseThrow()` throws `NoteNotFoundException` if empty — prevents NullPointerException.

## Layer 5 — Controller (`NoteController.java`)

The controller is the HTTP layer. It receives requests, calls the service, returns responses.

```java
@RestController
@RequestMapping("/api/notes")
public class NoteController {

    @PostMapping
    public ResponseEntity<NoteResponseDTO> createNote(@RequestBody NoteRequestDTO dto) { ... }

    @GetMapping
    public ResponseEntity<List<NoteResponseDTO>> getAllNotes() { ... }

    @GetMapping("/{id}")
    public ResponseEntity<NoteResponseDTO> getNoteById(@PathVariable Long id) { ... }

    @PutMapping("/{id}")
    public ResponseEntity<NoteResponseDTO> updateNote(@PathVariable Long id, @RequestBody NoteRequestDTO dto) { ... }

    @DeleteMapping("/{id}")
    public ResponseEntity<Void> deleteNote(@PathVariable Long id) { ... }

    @GetMapping("/search")
    public ResponseEntity<List<NoteResponseDTO>> searchNotes(@RequestParam String keyword) { ... }
}
```

### Annotations Explained

| Annotation | What it does |
|---|---|
| `@RestController` | `@Controller` + `@ResponseBody` — returns JSON automatically |
| `@RequestMapping("/api/notes")` | Base URL for all endpoints in this controller |
| `@PostMapping` | Handles HTTP POST requests |
| `@GetMapping` | Handles HTTP GET requests |
| `@PutMapping("/{id}")` | Handles HTTP PUT requests with path variable |
| `@DeleteMapping("/{id}")` | Handles HTTP DELETE requests |
| `@RequestBody` | Jackson converts incoming JSON to Java object |
| `@PathVariable` | Extracts value from URL path: `/notes/1` → `id = 1` |
| `@RequestParam` | Extracts value from query string: `?keyword=java` → `keyword = "java"` |

### HTTP Status Codes Used

| Response | Code | When |
|---|---|---|
| `ResponseEntity.status(CREATED).body(...)` | 201 | After creating a resource |
| `ResponseEntity.ok(...)` | 200 | Successful read or update |
| `ResponseEntity.noContent().build()` | 204 | After delete — no body |

## Layer 6 — Error Handling

### The Problem
Without error handling, hitting `/api/notes/999` returns a 500 with a Java stack trace — exposes internals, looks unprofessional.

### Custom Exception

```java
public class NoteNotFoundException extends RuntimeException {
    public NoteNotFoundException(Long id) {
        super("Note not found with id: " + id);
    }
}
```

### Error Response Shape

```java
@Data
@AllArgsConstructor
public class ErrorResponse {
    private int status;
    private String message;
    private LocalDateTime timestamp;
}
```

### Global Exception Handler

```java
@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(NoteNotFoundException.class)
    public ResponseEntity<ErrorResponse> handleNoteNotFound(NoteNotFoundException ex) {
        return ResponseEntity.status(HttpStatus.NOT_FOUND)
                .body(new ErrorResponse(404, ex.getMessage(), LocalDateTime.now()));
    }

    @ExceptionHandler(Exception.class)
    public ResponseEntity<ErrorResponse> handleGenericException(Exception ex) {
        return ResponseEntity.status(HttpStatus.INTERNAL_SERVER_ERROR)
                .body(new ErrorResponse(500, "Something went wrong.", LocalDateTime.now()));
    }
}
```

### How It Works

```
Controller method throws NoteNotFoundException
  └── Spring AOP intercepts it
        └── GlobalExceptionHandler.handleNoteNotFound() called
              └── Returns clean 404 JSON:
                    {
                      "status": 404,
                      "message": "Note not found with id: 999",
                      "timestamp": "2026-05-31T09:50:00"
                    }
```

## Full Request Flow

```
POST /api/notes with JSON body
        │
        ▼
Tomcat receives HTTP request
        │
        ▼
DispatcherServlet routes to NoteController.createNote()
        │
        ▼
Jackson converts JSON → NoteRequestDTO
        │
        ▼
NoteController calls NoteService.createNote(requestDTO)
        │
        ▼
NoteService maps DTO → Note entity, sets timestamps
        │
        ▼
NoteRepository.save(note) called
        │
        ▼
Hibernate runs: INSERT INTO notes (...) VALUES (...)
        │
        ▼
PostgreSQL saves the row, returns generated id
        │
        ▼
NoteService maps Note entity → NoteResponseDTO
        │
        ▼
NoteController wraps in ResponseEntity with 201 status
        │
        ▼
Jackson converts NoteResponseDTO → JSON
        │
        ▼
Client receives 201 Created with JSON body
```

## Common Beginner Mistakes Encountered

| Mistake | Fix |
|---|---|
| Wrong package — Spring can't find classes | `@ComponentScan` only scans the package of `@SpringBootApplication` and below |
| VS Code auto-imports wrong `Long` (imports `LongAccumulator`) | Always check your import statements |
| Calling repository directly from controller | Always go through the service layer |
| Exposing entity directly from controller | Use DTOs to control what goes in and out |
| Using `ddl-auto=update` in production | Use `ddl-auto=none` and manage schema migrations with Flyway |
